**The plugin is not releasable yet.** It depends on the `DoesTheDogDie` library via a local `ProjectReference`/checked-out-sibling path (`DtddClientPath`), not a published NuGet package, so a release build cannot restore it in a clean environment. It also needs the library's Phase 5 (prioritized work queue, budget forecasting) before it's safe to point at a real-sized library — without it, an initial scan has no way to spread lookups across the DtDD 5,000/month free-tier budget. See `docs/superpowers/specs/2026-09-18-dtdd-client-migration-design.md`, "Future work".

**Stale generated docs:** `_site/` was 69 tracked DocFX files documenting types deleted in this migration, one of which still displayed the retired bundled DtDD API key. It has been untracked (`git rm -r --cached _site`) and added to `.gitignore`; the files remain on disk and are regenerated by DocFX. Separately, that retired key was committed to `Constants.cs` in this public repository's history; it should be considered exposed and rotated/retired regardless.

## What's Working

- [x] API client fetches data from DoesTheDogDie.com
- [x] `DTDD_API_BASE_URL` env override (used by E2E to redirect to WireMock)
- [x] Movie metadata provider adds DTDD ID and warning tags
- [x] Series metadata provider adds DTDD ID and warning tags
- [x] Season/Episode providers inherit from parent series
- [x] Configuration options (ApiKey, EnableMovies, EnableSeries, TagPrefix, SafeTagPrefix, AddWarningTags, AddDescriptionWarnings, IncludeTopComment, MaxCommentLength, ShowAllTriggers, EnabledCategoryIds, EnabledTopicIds, DecisionThreshold, IntervalMass, ItemCacheDays, TaxonomyCacheDays)
- [x] Warning tags assert only confident verdicts (Beta-distribution confidence model; uncertain triggers get no tag). The old `MinVotesThreshold` / `UseConfidenceScoring` / `MinConfidenceThreshold` / `CacheDurationHours` / `RefreshIntervalHours` / `EnableBooks` / `HideSpoilerComments` settings were removed in the v3 migration
- [x] Description injection (Overview field) with marker-bounded section + locked-field respect
- [x] Background library scan service (auto-fetch for new items with IMDB IDs)
- [x] Scheduled refresh task (daily at 2 AM)
- [x] External ID display in Jellyfin UI (`IExternalId`)
- [x] External URL links to DTDD website (`IExternalUrlProvider`)
- [x] Real configuration page (`configPage.html`) incl. API key + test button, live topic/category picker (`GET Plugins/DoesTheDogDie/Topics`), budget display, and the Description Injection section (`AddDescriptionWarnings`, `IncludeTopComment`, `MaxCommentLength`)
- [x] Automated E2E harness (Testcontainers + WireMock) — verifies real Jellyfin integration without manual setup

## Known Issues / Blockers

| Issue | Impact | Workaround |
|-------|--------|------------|
| Season/Episode parent lookup untestable in unit tests | Low unit coverage on these providers | E2E suite covers real Jellyfin parent-series inheritance |
| Plugin.cs requires Jellyfin runtime | 0% unit coverage | Excluded from coverage; E2E exercises it via the real container |
| `DtddMovieProvider.FetchAsync` short-circuits when ProviderId set + `ReplaceAllMetadata=false` and both `AddWarningTags`/`AddDescriptionWarnings` are off | DTDD ID is kept but nothing is re-applied on partial refresh | Enable either option, or refresh with `replaceAllMetadata=true` |
| Plugin meta.json status defaults to Disabled | Won't load without explicit `"status": "Active"` | E2E fixture writes a correct meta.json automatically |

## Commands

```bash
# Build
dotnet build

# Unit tests only (fast, no Docker)
dotnet test --filter "Category!=E2E"

# E2E tests (Testcontainers spawns Jellyfin + WireMock)
dotnet test --filter "Category=E2E"

# Everything
dotnet test

# Unit tests with coverage
dotnet test --collect:"XPlat Code Coverage" --filter "Category!=E2E"

# Generate coverage report (requires ReportGenerator)
```
